# Playwright Framework Report

## 1. Framework Overview

This project is a Playwright test automation framework for the Rahul Shetty Academy client application.

### Main areas

- `tests/`: Test specifications.
- `pageObject/`: Page Object Model classes that contain page locators and reusable actions.
- `utils/`: Test data and helper utilities.
- `utils ts/`: TypeScript fixture and related test data.
- `playwright.config.js`: Playwright runner configuration.
- `playwright-report/`: HTML reports generated by Playwright.
- `test-results/`: Failure artifacts such as traces, screenshots, and error context.

### Page Object Model flow

The main client test uses `DataManager` to create and access these page objects:

1. `LoginPage`: Opens the application and performs login.
2. `DashBoardPage`: Finds a product, adds it to the cart, and opens the cart.
3. `CheckoutPage`: Verifies the product, enters checkout information, submits the order, and returns the order ID.
4. `OrderHistoryPage`: Opens order history and searches for the submitted order.

- `mairahk593@gmail.com` with `ADIDAS ORIGINAL`.

## 2. Current Test Structure

`tests/ClientAppPOM.spec.ts` currently contains two registered Playwright tests:

1. `Client login for all products`
   - Runs one test body.
   - Loops through both records in the JSON data.
   - Performs the complete login, purchase, and order-history flow for each record.
2. `Client App Login`
   - Uses the custom `testDataForOrder` fixture.
   - Verifies the login, product selection, and cart navigation flow.

The product loop is intentionally inside one `test(...)` declaration. Therefore, the two product records are iterations of one test rather than two separately scheduled Playwright tests.

## 3. Errors Encountered and Fixes

### Error 1: Duplicate test title `Client login for undefined`

#### Cause

The test title used `dataSet.productName`, but `dataSet` is an array. Arrays do not have a `productName` property, so every generated title became:

```text
Client login for undefined
```

#### Fix

Use the current loop item:

```javascript
test(`Client login for ${data.productName}`, ...)
```

Later, the product loop was moved inside one test because the desired behavior was to run both records as one test.

### Error 2: Duplicate test title `Client App Login`

#### Cause

The custom fixture test was declared inside the data loop. Playwright registered the same `Client App Login` title once for every data record.

#### Fix

The custom fixture test was moved outside the loop. It is now registered exactly once.

### Error 3: TypeScript error that `text` may be `null`

#### Cause

Playwright's `textContent()` method returns `string | null`. Calling `trim()` directly assumes that text always exists.

#### Fix

The comparison was made null-safe:

```typescript
if (text?.trim() === countryName) {
```

The safer long-term pattern is to keep the value typed as `string | null` rather than using `any`.

### Error 4: Checkout timeout while clicking `.action__submit`

#### Cause

The test submitted the order twice:

```typescript
await cartPage.placeOrder();
orderId = await cartPage.SubmitAndGetOrderId();
```

Both methods clicked the same submit element. The first click navigated to the confirmation page, so the second click waited for an element that had been removed or replaced.

#### Fix

The separate `placeOrder()` call was removed. `SubmitAndGetOrderId()` performs the single click, waits for the confirmation text, and reads the order ID.

### Error 5: Empty cart for `Adidas Originals`

#### Cause

Product matching in `DashBoardPage` is an exact, case-sensitive comparison. The data contained `Adidas Originals`, while the application catalog uses `ADIDAS ORIGINAL`. No product matched, so no item was added to the cart.

#### Fix

The data was corrected in `utils/placeorderTestData.json`:

```json
"productName": "ADIDAS ORIGINAL"
```

### Error 6: Email verification mismatch

#### Cause

The checkout test used a hardcoded email from the first user:

```typescript
const email = 'khanmaira632@gmail.com';
```

The second iteration logged in as `mairahk593@gmail.com`, so the expected and actual email values differed.

#### Fix

The expected email now comes from the active data record:

```typescript
await cartPage.verifyEmail(data.username);
```

### Error 7: Timeout waiting for `div li` in cart navigation

#### Cause

`DashBoardPage.navigateToCart()` clicked the cart and then waited for `div li`. That locator represents a cart item and is not a reliable navigation condition. It may not exist while the page is rendering or when the cart is empty.

#### Fix

The method now waits for the cart URL:

```typescript
await this.cart.click();
await expect(this.page).toHaveURL(/.*cart/);
```

Product existence is checked separately by `CheckoutPage.verifyProduct()` when the checkout flow requires an item.

### Error 8: Login field missing during the combined loop

#### Cause

After the first iteration, the browser remained authenticated. The next navigation therefore opened the application home page instead of the login page, and `#userEmail` was not available.

#### Fix

Before each data iteration, the test clears cookies and same-origin local storage, then opens the login page again:

```typescript
await loginpage.goTo();
await context.clearCookies();
await page.evaluate(() => localStorage.clear());
await loginpage.goTo();
```

### Error 9: Combined test exceeded the default timeout

#### Cause

The default test timeout is 30 seconds. One test now performs two complete end-to-end purchase flows sequentially, so the combined operation can require more time.

#### Fix

The combined test has a 60-second timeout:

```typescript
test.setTimeout(60 * 1000);
```

## 4. Playwright Configuration

The project currently uses one browser project:

- Chromium, headed mode.

The global defaults include:

- Test timeout: 30 seconds.
- Expect timeout: 5 seconds.
- Action timeout: 30 seconds.
- Navigation timeout: 60 seconds.
- Trace retention on failure.
- Screenshots enabled.
- HTML reporter enabled.

The `fullyParallel` setting is currently commented out. Local `workers` remains automatic unless the `CI` environment variable is set, in which case it is `1`.

## 6. Useful Commands

Run the targeted test file:

```bash
npx playwright test tests/ClientAppPOM.spec.ts
```

List collected tests without executing them:

```bash
npx playwright test tests/ClientAppPOM.spec.ts --list
```

Run with one worker:

```bash
npx playwright test tests/ClientAppPOM.spec.ts --workers=1
```

Open the latest HTML report:

```bash
npx playwright show-report
```
